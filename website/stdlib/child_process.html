child_process

Experimental — new, manually tested rather than conformance-suite covered.

A slice of Node's child_process module, in two shapes. spawnSync is one-shot: run a command, wait, take its output. spawn keeps the child alive and hands back a ChildProcess you can hold a conversation with — the same read/write/close shape as a Socket.

spawnSync spawn ChildProcess methods
child_process.spawnSync(command, args) Wasm: limited

(string, string[]) → { stdout, stderr, status } — runs command with args (no shell involved, matching Node's real spawnSync, not execSync's shell-string form -- safer by default, no shell-quoting needed), waits for it to exit. status is -1 if the command could not even be spawned (e.g. not found).

const r = child_process.spawnSync("echo", ["hello", "world"]);
console.log(r.stdout); // hello world
console.log(r.status); // 0
child_process.spawn(command, args) Wasm: limited

(string, string[]) → ChildProcess — starts command and keeps it running, with its stdin and stdout piped and held open. Stderr is inherited, so the child's diagnostics reach your terminal and an undrained stderr pipe can never deadlock it.

This is what a long-lived exchange needs — newline-delimited JSON-RPC over stdio, say, where one child serves many request/response round trips. spawnSync reads its child to completion and cannot do that.

// `cat` echoes each line of its stdin straight back on stdout.
let empty: string[] = [];
let cp = child_process.spawn("cat", empty);

cp.writeLine("ping");
console.log(cp.readLine()); // ping\n

cp.writeLine("pong");
console.log(cp.readLine()); // pong\n

cp.close();
ChildProcess methods
APIType
cp.write(data)string → void — raw bytes to the child's stdin, no terminator added
cp.writeLine(data)string → void — data followed by "\n"
cp.readLine()() → string — one \n-delimited line from stdout
cp.close()() → void — closes stdin and waits for the child to exit

readLine() keeps the trailing "\n" and returns "" only at true end-of-stream — the same contract as fs.createReadStream(...).readLine(). Stripping the terminator would collapse a genuine blank line and EOF into the same "", breaking a while (cp.readLine() != "") loop on blank input. The read blocks; there is no await integration yet.

Known limits. A single stdout line longer than the 64 KB reader buffer yields "". close() waits for the child to exit, with no kill or timeout escape hatch, so a child that never terminates hangs it. A failed spawn degrades to a no-op handle rather than throwing. There are no signals, no pty, and no stderr capture — see the roadmap.
